\section{Reference implementation boundaries}
\label{sec:refimpl}
Two implementation-level differences from the reference code, moved here
because they are boundary conditions rather than results. The reference's
rank-1 path does not compile on a 16\,GB TPU chip at $d{=}512$,
$N{=}16384$: the compiler allocates 24.1\,GiB of temporaries,
reproducible with no TPU via the compile-only probe in the repository,
the same pathology this instrument diagnosed and works around; the same
cell runs here at 245\,ms. And the reference declines embedding tables
outright, while the instrument carries that seam
(Section~\ref{sec:design}). Both are properties of the released
implementations, not of the algorithms.

\section{Reproduction}
Every figure and generated table regenerates from a committed script against
a committed results directory, and every reported result traces to a script,
configuration, and record. Each results directory's README documents the
session that produced it (platform, commit, environment, cost, and any
incident). The figure and table map: F1, F2 and F2b from
\texttt{plot\_paper.py}; F4 from \texttt{plot\_cost.py}; F5 from
\texttt{experiments/phase0/plot.py}; F7 and F7b from \texttt{plot\_e13.py}; F8 from
\texttt{plot\_e14.py}; the appendix grids (M1--M3, both platforms) from
\texttt{plot.py} against each platform's results directory;
Tables~\ref{tab:tb1}, \ref{tab:tb2}, and~\ref{tab:tb3} from
\texttt{tb1.py}, \texttt{tb2.py}, and \texttt{tb3.py};
Table~\ref{tab:tb4} from
\texttt{analysis\_e15.py}; Table~\ref{tab:tb5} from
\texttt{tb5\_e17.py}; and Table~\ref{tab:tb6} from
\texttt{tb6\_e16.py}. Each table
script accepts \texttt{--latex} and writes the exact file this document
inputs. Table~\ref{tab:tb6}'s predicted columns are the committed E1 fit
and the 0.53 correction, both frozen (rounded) in \texttt{e16-gate.yaml}
and \texttt{e16-stage2.yaml} before the runs; nothing in them is fit to
E16's measurements. The test
suite runs on CPU with no network; the multi-device logic is exercised on
eight simulated devices, so correctness properties (including the
device-count invariance test) are checkable without any accelerator, and the
two TPU compile probes
(\texttt{probe\_lr1.py}, \texttt{probe\_eggroll\_tpu.py}) reproduce
the compiler-level claims from any Linux machine. Source and result records
are at \url{https://github.com/andreshernandez-spec/shardes}. With the project
extras installed, \texttt{make -C paper} regenerates all five tables and
builds the PDF; the provenance paragraph in Section~\ref{sec:setup} names the
frozen submission tag once assigned.
